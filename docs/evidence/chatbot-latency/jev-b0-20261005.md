### Every accepted or near-accepted error

| Question | Label | Jev | Confidence | Write score | Outcome at 0.8 + guard |
|---|---|---|---:|---:|---|
| `شحال من امتحان كاين هاد الشهر؟` ("how many exams this month?") | needs_llm | upcoming_exams | 0.77, 0.77, **0.82** | 0.04 | **Accepted once: the gate failure.** The reply would list the next five exams instead of counting this month's |
| `bdel la date dyal l'examen Zzbench l lundi` (a write) | write_request | upcoming_exams | 0.81–0.87 | 0.58–0.64 | Rejected only by the write guard |
| `كتب ليا شي قصيدة على المدرسة` ("write me a poem") | needs_llm | write_request | 0.71–0.83 | 0.31–0.39 | Rejected only by the write guard |

"How many exams this month" is chosen as upcoming exams in all four languages
(French 0.65–0.68, English 0.60–0.64, Arabic 0.47–0.58, Darija 0.77–0.82). It is
a systematic confusion between counting exams in a period and listing the next
ones, not a one-off.

Without the write guard, at 0.8 there were 5 wrong samples (3 questions),
including the write above. **The guard is required, and its margin on that write
is thin (0.58).**

31 held-out Darija write samples were not accepted as writes and would go to
the model instead. That is safe, because the model path blocks writes.

## What the threshold curve shows, and what it cannot

At 0.9, the held-out set had **0 wrong among 150 accepted questions** (77.3%
coverage). That threshold was **not** predeclared: choosing it after seeing the
test results is fitting to the test set, so it is **not** evidence that 0.9 passes.
This test set is now spent for threshold choice.

## Limitations

- One author wrote the questions and the intent wording; a native-speaker set
  remains outstanding, and Darija and Arabizi coverage numbers depend on how the
  author wrote them.
- Repetitions are not independent; claims count questions, not samples.
- Single-turn questions only; no reply was rendered or checked.
- One machine, one evening; the 4.6 s outlier shows tail latency needs the deadline.

## Next step options (owner decision; nothing started)

1. **B0 retry with a fresh held-out set.** Tune on dev for exam counts within a
   period (wording v4, or keep `upcoming_exams` above a higher per-intent
   threshold), then predeclare and test on **new** questions: ideally the
   native-speaker set plus new assistant-written ones. About $0.05.
2. **Narrow the scope.** Exclude `upcoming_exams` from Jev (leave it to the
   regex and the model) and retest the other intents on a fresh held-out set.
3. **Stop.** Keep Jev off and keep this report.
