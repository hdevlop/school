# Full 50-question baseline — 2026-10-03

All 50 cases of `datasets/chatbot-latency/questions.json` (10 each in English,
French, Spanish, Modern Standard Arabic and Darija), once, on a production
build (`bun run build && bun start`), so no dev hot reload could interrupt the
run. Saved model `openai/gpt-oss-120b`, default OpenRouter routing; admin
account; year 2026-2027; seed:demo data. Pins: `najm-chatbot` 2.0.5,
`najm-rag` 2.1.4, `najm-mcp` 2.2.3. Tool routing on Qwen3 Embedding 0.6B with
the Darija rewrite. [json](full50-20261003.json)

```sh
bun --env-file=apps/dashboard/.env.local scripts/chatbot-benchmark.mjs --max-requests=50
```

## Correctness

| | en | fr | es | ar | ary | All |

| As scored | 9/10 | 10/10 | 10/10 | 10/10 | 10/10 | 49/50 |
| Re-scored with the table fix | 10/10 | 10/10 | 10/10 | 10/10 | 10/10 | **50/50** |

The one failure, `classes-en`, was a correct English answer whose table listed
the stored French class descriptions ("Cours Préparatoire"); the language check
read the table. `scripts/chatbot-language.mjs` now skips Markdown table data
rows (headers stay) and pins that reply in a test. The earlier 40-question run
on 2026-10-03, before the read-only marks, teacher count and Darija routing,
passed 27/40.

All 50 completed; none of the 10 write requests ran a write. The model called
`announcements_create` four times and the chat adapter blocked it each time;
the other write cases stopped earlier (no matching student, or no tool call).

The model and the provider stream are about 93% of an answer at p50; School's own
work is under 0.5 s even at p95. One run of 50 is smoke coverage, not a p95
estimate (section 6.2 asks for about 100 observations per group), and
provider speed varies about 2× between runs on the default route.
