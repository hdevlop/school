# Jev Stage A: intent classification probe (2026-10-05)

Raw samples and every summary: [jev-probe-20261005.json](jev-probe-20261005.json).
Corpus: [jev-intents.json](../../../datasets/chatbot-latency/jev-intents.json) plus
all 50 cases of [questions.json](../../../datasets/chatbot-latency/questions.json).
Runner: `bun --env-file=apps/dashboard/.env.local scripts/chatbot-jev-probe.mjs`.

## What ran

- Model `typesafe/jev-1.13` (served build `jev-1.13-20260917`, provider TypeSafe)
  through OpenRouter's Decisions API (`/api/alpha/decisions`) with the existing
  OpenRouter key. No school app, school tool, chat model or database was used.
- One `choice` question over nine intents (`scripts/chatbot-jev.mjs`) and one
  `noul` write question per request. 136 synthetic questions × 3 repetitions =
  408 requests, sequential, from the development machine. 0 errors, 0 timeouts.
- Split: the 50 base cases plus 18 new ones are **dev** (threshold choice); 68
  new paraphrases, qualified questions, how-to questions, out-of-scope topics and
  Latin-script Darija are **test**.
- One extra smoke request preceded the run ($0.000036246).

## Results

### Accuracy (test split, 68 cases × 3)

| Language | Samples | Top-choice accuracy | Wrong among accepted (≥ 0.8) | Coverage of deterministic cases (≥ 0.8) |
|---|---:|---:|---:|---:|
| French | 48 | 100% | 0 of 27 | 100% |
| Arabic | 36 | 100% | 0 of 21 | 100% |
| Darija (Arabic script) | 48 | 100% | 0 of 24 | 80.0% |
| Darija (Latin script) | 27 | 96.3% | 0 of 17 | 81.0% |
| English | 27 | 100% | 0 of 21 | 100% |
| Spanish | 18 | 100% | 0 of 15 | 100% |
| **All** | **204** | **99.5%** | **0 of 125** | **92.6%** |

Darija is classified correctly but with lower confidence, so at 0.8 about a fifth
of deterministic Darija questions still fall back to the model. The write guard
(choice and write answer must agree) changed nothing at 0.8.

Dev at the same 0.8 threshold: 97.1% top-choice accuracy, 0 wrong among 162
accepted, 96.4% coverage. No threshold from 0.5 to 0.99 accepted a wrong answer
on either split. The dev-selected threshold was the grid minimum, 0.5, so the
threshold is not tightly determined by this corpus.

Every misclassification (7 of 408 samples, 3 cases):

| Case | Label | Jev | Confidence | Write probability | Effect |
|---|---|---|---:|---:|---|
| `مسح القسم Zzbench` (ary, ×3) | write_request | needs_llm | 0.60–0.71 | 0.65–0.72 | Safe: falls back to the model |
| `sjel Zzbench Qqtest ghayb lyoum` (ary-latn, ×3) | write_request | attendance_today | 0.35–0.37 | 0.47–0.49 | Rejected below 0.5; write guard also near its boundary |
| `kifach nzid tilmid jdid?` (ary-latn, ×1) | needs_llm | student_count | 0.34 | 0.44 | Rejected below 0.5 |

The weakest input is Latin-script Darija (Arabizi): it produced both
low-confidence errors, one of which was the only unstable case across repetitions
(135 of 136 cases gave the same choice every time).

### Baseline: today's regex templates

`schoolReplyTemplate` (read from source, run locally) matched 26 of 101
deterministic-label cases overall (25.7%) and **1 of 45 in the test split
(2.2%)**, with no wrong match. It handles only exact French, Arabic and Darija
phrasings; English, Spanish and Latin-script Darija get 0%. Jev's gain is
coverage of paraphrases, not precision: both made no accepted error here.

### Cost

- Jev-reported cost: **$0.014694750** for 408 requests, 349,875 input tokens
  (858 per request), about **$0.000036 per classification**.
- Observed key-usage delta across the run: $0.811308406 − $0.792264894 =
  **$0.019043512**. That exceeds reported cost plus smoke call by about $0.0043.
  Other use of the key during the window was not excluded, so the gap is
  unattributed, not a confirmed Jev charge.
- At the observed ~$0.0011 per model reply (2026-10-04), one classification is
  about 3.3% of a model reply. Jev pays for its own calls if it moves at least
  about 3.3% of model-path requests to deterministic replies. The real share
  depends on School's traffic, which this corpus does not represent.

## Disposition

**Stage A: no accepted error, latency inside the target and large coverage gain
on this synthetic corpus. The 98% precision floor is not yet established.**
Stage B is justified as an experiment, not as adoption.

- Precision: 0 wrong of 125 accepted test samples (44 unique cases). With 0
  errors in 44 unique cases, the 95% upper bound on the error rate is about 7%
  (rule of three), so this **does not** establish the 98% floor. About 150 unique held-out cases with
  no error would be needed for that claim.
- Writes: no write was accepted as a read; the Arabizi attendance write came
  within 0.03 of passing the write guard. The server's write blocking, not Jev,
  remains the authorization boundary.
- Latency: p95 433 ms, inside the ~500 ms candidate deadline.
- Coverage: 92.6% of deterministic test cases at 0.8, versus 2.2% for regex.

## Limitations

- The same author wrote the questions and the intent wording; the split is not an
  independent evaluation. Repetitions are not independent samples.
- Single-turn synthetic questions only: no follow-ups, conversation history, typos
  at scale or real school traffic. No native-speaker review of the new Darija.
- Classification only. No reply, tool or template ran; answer correctness, end-to-
  end latency and the small-LLM path are untested (Stage B).
- One machine, one afternoon; vendor latency can vary by time and region.

## Next step (Stage B, not started)

Wire Jev behind a default-off switch, **in parallel with** the existing routing
embedding so a fallback does not wait for it. Then benchmark against today's path
with the existing runner, adding: more unique held-out cases (especially Arabizi
and writes), a conservative starting threshold (0.8 with the write guard), and
conversation follow-ups, which must stay on the model path.
