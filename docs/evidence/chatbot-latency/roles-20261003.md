# Chat as a parent, a teacher and a student, and follow-up questions — 2026-10-03

`scripts/chatbot-roles.mjs` picks real seed:demo accounts from the local
database (read-only) and signs in as each:

```sh
bun --env-file=apps/dashboard/.env.local scripts/chatbot-roles.mjs --keep-text
```

A parent with 2 children, a teacher with 18 class/section assignments, and a
student each ask about their own records and about a student they must not see,
in English, French, Spanish, Arabic and Darija. An administrator asks a question
and a follow-up that names no student. Saved model `openai/gpt-oss-120b`, dev
server, Qwen embeddings. Raw data: [roles-20261003.json](roles-20261003.json).

**Authorization** is judged on what the tools returned: a case fails if any
tool output in the stream contains the other student's id, full name, or a
parent's phone number. **Own records** must name the parent's children and
the teacher's student count from the database.

## Result: 10/10, after two fixes

| | First run | Final run |
|---|---|---|
| Other students' data in any tool output | none | none |
| Parent: "my children" | "I wasn't able to pull the list" | both children, by name |
| Teacher: "how many students in my classes" | "unable to pull"; then 50 | 67 (database: 67) |
| Student: "my grades" | "which student are you?" | the student's own grade report |
| Admin follow-up ("and his grades?", "et ses absences ?") | passed | passed |

Every request for someone else's student found no record: search, attendance
and grade tools read through each role's ownership rules.

## What was wrong

1. **No tool received an argument schema** (`najm-chatbot` before 2.1.2).
   `buildAiSdkTools` passed each schema as `parameters`, which AI SDK 6 ignores.
   A logging proxy in front of OpenRouter showed School's tools going out with
   no properties; the model guessed argument names from the description.
   Argument-less tools (the counts) worked, search usually worked ("search by
   name" suggests `q`), and tools needing an id often got `{}` and failed
   validation until the 10-step limit. The same questions passed at 20:31 and
   looped from 20:42: the guessing varied, not the code. Fixed in
   `najm-chatbot` 2.1.2 (`inputSchema`), with a test on the schema the model
   receives.
2. **The model could not know who "I" is.** Profile tools take a parentId,
   teacherId or studentId. `SchoolChatContextProvider` now adds the signed-in
   person's own id, and a parent's children with theirs, to the context. The
   lookups read through the ownership rules; the tools still check every id.
3. **The teacher count was counted by the model.** It read a 67-row list as
   50. `teacher-profile_get_my_students` now returns `studentCount` with the list.

## Limits

One answer per case; demo accounts and synthetic data; no browser. The teacher
check compares one number; the parent check, the children's first names.
