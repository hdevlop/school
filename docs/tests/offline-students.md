# Phase 1 Students read slice

Updated: 2026-10-24 (Africa/Casablanca). The bounded Phase 1 Students proof passes locally in Chromium, Firefox and WebKit. Physical-device and rollout gates remain separate. No publication or deployment is claimed.

## Endpoint and panel ledger

All registrations use GET, exact normalized paths and **no query parameters**. A dated roster, new filter or arbitrary URL is not covered. Existing table search, sorting and pagination operate on the complete, authorized Students list as before. The dispatcher's response is `{ data: serverBody }`; the existing per-module APIs still return that `.data`. Language is part of each projection key. A replacement downloads the current language; another language requires its own successful download.

| Path | Scope / permission | Projection and dependency |
| --- | --- | --- |
| `/students` | Account + selected year; `read:students` and complete coverage | Actual authorized `StudentService.getAll()` response, including that year's placements. Empty is valid only when the downloaded server response is empty |
| `/students/:id` | Same; only downloaded list members | The `getById()` response. For a listed student that is its row from the same owned, year-scoped `getAll` query (filtered to the id), so the downloaded list supplies each detail without another query |
| `/students/:id/parents` | Same Student policy as the online endpoint | The linked-parent projection, read for every listed student in one query with the endpoint's `parentSelect` fields and name order. The existing online endpoint authorizes this through the Student, rather than a separate Parent list permission |
| `/students/:id/enrollments` | Selected-year download containing the endpoint's explicit all-year history; administrator/principal only | The enrollment response required by Overview's enrollment actions, read for every listed student with two queries (`StudentEnrollmentService.listByStudents`, sharing the single-student select shapes). Uses the same centralized administrator role group as the existing route |
| `/classes` | Account + selected year; `read:classes` | Actual `ClassService.getAll()`, using the existing owned/year-scoped repository and the shared permission guard. Includes the sections required by the existing list filters |
| `/settings/public` | Explicit shared scope; authenticated Students-read enrollment | Existing public-settings projection only, including the captured business date |
| `/academic-years` | Explicit shared scope; authenticated enrollment | Existing role-filtered year list. The same selected-year owner restores the account's tab/local selection |

The detail slice displays identity, sidebar identity/placement, Overview, linked parents and authorized enrollment controls. Sidebar attendance, grade and financial statistics use an explicit unavailable notice and an em dash. Attendance, Grades, Fees, Transport and Alerts panel content is unavailable; those components are not mounted by the public TabsContent adapter. Existing eager sidebar/alert hooks remain unchanged and receive typed unavailable results from the dispatcher; no finance endpoint is allowlisted, fetched by the shell, or downloaded. Public default student/parent base-image URLs are precached; versioned image requests/private attachments are not covered and can fall back to initials.

Unregistered GETs use the existing online transport in an ordinary Next document. In the independent shell they return `OFFLINE_DATA_UNAVAILABLE`, including after reconnect. The shell refuses every read made before its runtime connects, so it connects in a layout effect, ahead of the first query any of its views subscribes; an ordinary document mounts its runtime before the page and sends such reads online. Writes, multipart uploads, auth and AI remain on their existing transports; there is no queue, delayed replay or local save-success state.

**Deadline fallback is disabled for every route.** No latency measurement or late-response bridge is claimed. Slow requests remain pending. Only recognized fetch connection failures select local fallback/outage mode; 401/403/404, validation, abort, timeout and 5xx errors retain their failure semantics. Recovery requests are deduplicated with bounded backoff. A retained shell permits registered online reads only after the protocol/schema and fresh-authorization handshake succeeds.

A 403 for a capability the account never held (for example, a parent without Class-list access) stays refused without revoking its permitted Students slice. A 403 for previously granted coverage and every 401 lock private access. Any HTTP recovery response ends known-connection-outage mode, so later server failures cannot keep returning cached success.

## Storage and access

Published exact pins are `najm-database@2.3.3` and its `fast-idb@0.3.1` peer; both local reference versions match. This supersedes the plan's earlier 2.3.2/0.3.0 adoption target. School consumes published packages, with matching overrides and the Bun lockfile.

An IndexedDB installation registry creates the stable installation ID/epoch atomically. A localStorage pointer selects the current account database and fences account switches and mutation attempts; it cannot authorize reads. The authoritative access row must match that selection fence. A pointer alone can deny access but cannot grant it. Each account's package replica owns its records, snapshots and single metadata/access row. Najm's offline helper uses a transactional compare-and-swap adapter on that row, explicitly bounded to eight hours. School commits cached display metadata in the same transaction as fresh enrollment, so interruption cannot leave mismatched access/display generations. Its persisted clock high-water check survives reopening. Logout, known refusal (including a session the server refuses at refresh), account mismatch, expiry and clock rollback deny private reads without deleting records or future work.

Online startup, successful token refresh, visibility resume, reconnect and a 15-minute schedule request fresh server authorization. Each downloads only coverage that is missing, in another language or older than 15 minutes; a reconnect and an edit of downloaded data (below) replace it regardless, and so does the first renewal after a failed one, whatever starts it: server data may have changed meanwhile, and a browser need not fire `online` on reconnecting (Firefox under Playwright did not). The server checks the current active account, role and effective permissions from PostgreSQL. Generation identity includes permission and ownership membership: parent links, teacher assignments, every placement of an enrollment placed in one of the teacher's sections, and a student's own account. A known change, including a student moved into or out of a teacher's section, makes old coverage unusable. A failed request cannot renew expiry. Only after enrollment and the atomic metadata commit can the temporary display record be removed. Accounts outside this first Students slice retain Phase 0 display-only shell preparation; it can never replace an account's real expired/revoked entitlement.

The shared renewal scheduler owns those event bindings and the advisory interval; one queue coalesces concurrent triggers into one in-flight request and at most one follow-up. A still-ungranted role gets at most one migration-token refresh per selected account, avoiding a `tokenRefresh`/refused-grant loop. Controlled-clock tests use the published replica access helper to cover a nine-hour online session, the 14:00 interruption with access until 22:00, failed renewal without extension, exact expiry, the 15-minute interval, sleeping/hidden tabs, immediate visible resume, revocation and late-grant CAS refusal. These accelerated checks do not claim physical device suspension acceptance.

The independent entry uses a public, build-only hook adapter for cached display identity and read permissions. It keeps `isAuthenticated: false`, no access token and `snapshot.session: null`; it never hydrates a cached online session. A language, theme or time-zone chosen in the shell is stored with its record (the prepared display record without private access, the cached presentation with it) and overrides any record read later in that document, so a renewal re-enrolls the chosen values instead of restoring older ones. Other Najm auth exports forward to their original public entry. The same provider and QueryClient remain authoritative in each mounted application.

Server snapshots use repeatable-read transactions through the existing Najm transaction/request/year context. Existing Students/Class services and their owned repositories provide the list and classes; parents and enrollment history for all listed students are batched (above), so a 2,000-student scope needs a handful of queries rather than several per student. Expired download rows are deleted before, not inside, the snapshot transaction: two repeatable-read snapshots deleting the same rows would fail with a serialization error. There is no arbitrary tool/controller invocation API. Immutable download rows persist pages for five minutes; every page rechecks account, installation, generation and year. PostgreSQL `timestamptz` avoids host-time-zone reinterpretation of expiry. Each page has at most 500 replica projections and 1 MiB canonical JSON; an individual oversized projection and a Students scope above 2,000 members are refused with 413. Incomplete downloads leave the prior complete generation intact. The durable sequence is a **read baseline**, not a claim that current domain writers expose future command revisions.

Online writes to routes that feed downloaded data (`offlineWriteAffectsReads` in `@sms/contracts/offline`: students, parents, enrollments and placements, classes, sections and their staff, settings, academic years) change the durable deny fence before invalidating retained scopes and sending, including a lost response; a burst of such successful writes schedules one replacement three seconds after the last. Other writes (attendance, grades, finance, chat, search) leave retained copies as they are; the 15-minute replacement reflects any indirect effect. If IndexedDB invalidation fails, an old access-row binding cannot match the new selection. Before fresh enrollment can bind that selection, every old scope must be retired; a replacement must finish before it becomes readable. Late callbacks from the prior selection cannot bind a new grant. Clock updates preserve the old binding rather than accidentally restoring access. This remains one access authority, with the pointer serving only selection/denial.

Losing access (a lock, a refusal, a changed generation) hides retained copies from mounted queries once per loss, not again on each later check. The independent shell shows only retained copies, so all of its queries are hidden. An ordinary online page hides only the queries it updated after first displaying a retained copy; server results stay as they would without offline access. A different account (logout, an account switch, another tab's account) hides and clears every query. The first account a page resolves is not a switch, so its initial fetches are untouched. Another tab's edit or lock only moves the selection fence, which local reads re-check themselves. A server response is discarded only when the signed-in account changed while it was in flight.

The selected account database is opened once and shared by every selection of it; each selection keeps its own fence view, so a download begun before an edit keeps its connection while the new view binds the next grant. Only an account switch or logout closes the previous account's connection.

Read-storage failures return typed unavailable results. Injected quota failures during snapshot activation and enrollment roll back the whole transaction, preserving the previous complete data and matching access/display metadata. Persistent storage is requested when supported. Removing site data removes readiness; no remembered boolean restores it. Real device exhaustion/recovery and simultaneous denial of every storage mechanism still require physical acceptance; ordinary online transport is preserved when offline-storage maintenance fails.

## Rollout and repeatable checks

Migration `0077_offline_read_snapshots.sql` is additive and idempotent. It creates the short-lived download table, adds `read:offline` and gives that capability to existing standard School roles. It neither resets custom grants nor grants any resource permission. Fresh-install permission/role catalogs include the same capability. Custom roles require an operator grant; existing `read:*`, `*:offline` or `*:*` retain Najm's normal wildcard meaning. Revoking a concrete grant cannot override a wildcard; operators must narrow that wildcard too.

The main local `school` database had unrelated pending migrations, so the default migration runner was **not** executed against it. The new migration was exercised only against marked local `school_history_test`; its migration journal was not advanced past unrelated work. A release must apply the normal ordered migration queue and verify effective grants and restored-session renewal before claiming rollout. No production data was changed.

Commands from the root:

```text
bun run test:offline
bun run test:offline:transport
bun run test:offline:reads
bun run test:offline:lifecycle
bun run test:offline:renewal
bun run test:offline:navigation
bun run test:offline:errors
bun run test:offline:browser
bun run test:config

bun run test:boundaries
bun run lint
bun run typecheck
bun run i18n:check

```

`test:offline:transport` requires the existing local history fixture/credentials from `.env.local`. It checks the marker, applies only this additive migration there, creates a temporary restricted parent and link, and cleans those temporary records/grants. It checks real HTTP envelope parity in two years, restricted ownership, year refusal, immutable page checksums/limits and cross-account page refusal. It never touches main-school people or credentials.

WebKit private-session runners use a generated loopback HTTPS certificate and Next's public custom-server API to serve the same completed production build. HTTP cannot prove the production session there: WebKit withholds Secure cookies and obeys the CSP's HTTPS asset upgrade. OpenSSL comes from PATH or Git for Windows; `OFFLINE_TEST_OPENSSL` can name its executable. The fixture creates its own OpenSSL config, avoiding unrelated machine `OPENSSL_CONF` settings. No system/browser trust store is changed. Certificate-error tolerance is confined to the isolated test profile; the Node child trusts this fixture certificate and the health probe explicitly verifies it. Production cookie/auth/CSP policy remains unchanged. Generated certificates and browser session profiles stay ignored under `.cache`.

`test:offline:reads` requires a completed production build. It starts an isolated production server against that same fixture, signs in through REST, starts at `/home`, waits for the controlling worker and actual access/complete snapshot rows, then stops its server. It checks the historical list, a detail never visited online, Overview/placement, unavailable summaries/panels, Back, reload and a fresh browser process while `navigator.onLine` remains true. `OFFLINE_BROWSERS=chromium,firefox,webkit` selects engines. Diagnostics open only existing IndexedDB databases and abort accidental upgrades; polling must never create an empty replica before the application creates its stores.

`test:offline:lifecycle` uses Chromium/Firefox/WebKit and the same marker-checked fixture. It creates only its own temporary admissions and restricted parent account, exercises the actual Students edit form, makes isolated REST edits/deletion while the browser is offline, then checks reconnect, cross-tab logout, account switching and server deactivation. After refusal it closes every browser window, stops its own server and opens a fresh browser process against the same profile with `navigator.onLine=true`; retained private records remain unavailable. The real DELETE endpoint handles the temporary admission's academic dependencies through its existing service/repository; financial-history protection is unchanged. Failure/final cleanup removes only the runner's exact IDs and test-created enrollment history. An absent fixture parent role is created with just the two required read permissions and removed afterward; an existing role is never broadened. Each runner uses a distinct private client address at the loopback fixture's normal trusted-proxy boundary to avoid consuming the owner's login-rate bucket; rate limiting stays enabled.

`test:offline:renewal` checks the actual Chromium/Firefox/WebKit production runtime. It accelerates browser timers while keeping `Date` near real server time: a 15-minute check must obtain a real server grant even when token refresh is refused; a single challenged Students read then causes the real client's successful `tokenRefresh`, which must immediately renew access in the same mounted document. Failed reconnect authorization preserves the old access/display expiry; reconnect recovers. A temporary account/role with `read:students` but no `read:offline` proves refused grants settle without a refresh loop or entitlement. Only those exact auth records are created and removed; existing grants, school records and rate-limit configuration remain unchanged. This runner blocks service-worker registration in its test context so Playwright's injected HTTP challenges reach the actual client consistently across engines; read/navigation/lifecycle runners separately exercise the real worker. Combined with the controlled-clock helper tests, this separates event wiring, server-issued grants and long-window arithmetic without manufacturing an online session or cached records.

`test:offline:navigation` starts in the real online Students table and clicks the unchanged, non-anchor row callback only after stopping its server. It asserts the failed RSC attempt, subsequent native document navigation, unvisited private detail, profile Back button, browser Back/Forward and reload with browser connectivity still enabled. No feature, framework or online-router implementation is substituted.

The browser error audit records WebKit's native fetch/resource/closing-context diagnostics separately. Fetch diagnostics require matching failed requests, worker resource failures require failed public-image/favicon requests, and stopped-context diagnostics require an explicit browser close or a navigation of that page in the previous five seconds: a signed-in online page stores the shell's logos and prunes old shell caches on load, and a navigation (a logout redirect, a test's own) can stop that work mid-call. Actual JavaScript `error` and `unhandledrejection` events still fail. `test:offline:errors` is an independent negative control without a database: deliberately uncaught exceptions and rejected promises, including a native-diagnostic lookalike and a thrown stopped-context lookalike right after a navigation, must be detected in every selected engine.

## Current evidence and remaining release gates

Focused replica/dispatcher/server tests, HTTP fixture parity, source/build and browser results are recorded with final counts in the Phase 1 entry of [offline acceptance](offline-read.md). Retained logs/screenshots use `.cache/offline-phase1-*` and `.cache/offline-reads-*`.

Chromium, Firefox and WebKit pass actual private reads with the isolated production server stopped, real form-edit freshness, reconnect after server edits/deletion, cross-tab logout, a restricted parent account switch and server refusal followed by a fresh browser process. A session the server refuses while the online app is open also locks: with `najm-auth@6.10.0`, `sessionExpired` reports `reason: 'refused'` for a refresh answered 401 or 403, and the runtime locks retained copies on it before the page leaves for sign-in. `'rate-limited'` and `'unavailable'` (network errors, 5xx) keep them readable. Before, the lock depended on an offline-routed read or a renewal receiving the 401 ahead of that redirect, so a user deactivated with the online app open could keep a readable copy until the eight-hour window ended. Firefox under Playwright loads the online document for offline navigations, so it exercised that path: the refusal step failed about one run in three, and now passes five runs of five. Production renewal event wiring and the already-open online Students row transition pass in all three engines; controlled-clock tests establish the maximum interval and sleeping-tab resume behavior. The earlier WebKit HTTP/session blockage is superseded by the HTTPS fixture. Physical suspension, representative-phone measurements, all-role/module expansion, physical Android/iOS durability, production migration/deployment, quota/device recovery, attachment availability and owner visual acceptance remain separate gates. Per-route deadline measurement and its late-response bridge remain deliberately disabled work, not a passing timeout-fallback result.
